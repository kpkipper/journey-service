# Moments (รูปและวิดีโอ) Implementation Plan (MVP แผน 4 จาก 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** คนในทริปแปะรูป/วิดีโอลงใน Day หรือ Plan ได้ ระบบลบ EXIF/GPS ทุกไฟล์ ย่อรูปและทำ thumbnail ให้ และคนดูเห็น Moment ตามกฎ privacy เดียวกับทริป

**Architecture:** ไฟล์อยู่ใน Firebase Storage (bucket ของ GCS) แบบ private ทั้งหมด browser อัปโหลดไฟล์ดิบตรงไปที่ bucket ผ่าน signed PUT URL (ไฟล์ใหญ่ไม่ต้องวิ่งผ่าน API) แล้วเรียก `complete` ให้ API ดึงไฟล์ดิบมา process (รูป: decode แล้ว encode ใหม่เป็น JPEG = EXIF หายหมด; วิดีโอ: ffmpeg remux ตัด metadata และ data track) เก็บไฟล์ที่ process แล้วและลบไฟล์ดิบ การอ่านใช้ signed GET URL อายุสั้นที่ API ออกให้หลังผ่าน `PrivacyService` แล้วเท่านั้น ตอน dev/test ใช้ `LocalStore` (เก็บใน disk + URL ที่ API เซ็นเอง) แทน Firebase

**Tech Stack:** เหมือนแผน 1–3 + `cloud.google.com/go/storage` (เลือก version ที่ go.mod ของมันต้องการ go ≤ 1.24.1, ห้ามขยับ `go` directive/toolchain), `github.com/disintegration/imaging` v1.6.2, `golang.org/x/image/webp`, ffmpeg/ffprobe (binary ใน Docker image)

**Spec:** `docs/business-requirements/2026-11-08-social-trip-sharing.md` ข้อ 6.2 (ข้อ 4, 6), 7.6

**Base:** branch `feature/moments` แตกจาก `feature/privacy-status`

## Global Constraints

- Moment ต้องผูกกับ Day เสมอ (`day_id` บังคับ) และผูก Plan ได้ (`plan_id` ว่างได้ ถ้าส่งมาต้องเป็น plan ของ day นั้น) ไม่มีโพสต์ลอย ๆ
- `kind`: `photo` | `video`. `status`: `pending` (รออัปโหลด) | `ready`. ผู้ใช้อื่นเห็นเฉพาะ `ready`
- รูป: ไฟล์ดิบ ≤ **10 MB** (10485760 bytes), รับ `image/jpeg`, `image/png`, `image/webp` เท่านั้น (เช็คจาก bytes จริง ไม่เชื่อ content type ที่ client บอก), ≤ **50 ล้าน pixel** (เช็คจาก `image.DecodeConfig` ก่อน decode), หมุนตาม EXIF orientation ก่อน encode
- รูปที่เก็บ: full = JPEG quality 85 ด้านยาวสุด ≤ **2048** px (ไม่ขยายรูปเล็ก), thumb = JPEG quality 80 ด้านยาวสุด ≤ **480** px
- วิดีโอ: ไฟล์ดิบ ≤ **100 MB** (104857600 bytes), รับ `video/mp4`, `video/quicktime`, ความยาว ≤ **60.5 วินาที** (ffprobe), เก็บเป็น MP4 แบบ `-c copy` (ไม่ transcode) + `-movflags +faststart`; ถ้า codec เป็น hevc ใส่ `-tag:v hvc1`; thumb = JPEG ด้านยาว ≤ 480 จากเฟรมแรก
- คำสั่ง ffmpeg ต้องเลือกแค่ video track แรก + audio track แรก (`-map 0:v:0 -map 0:a:0?`) และตัด metadata ทุกระดับ: `-map_metadata -1 -map_metadata:s -1 -map_chapters -1 -fflags +bitexact -flags:v +bitexact -flags:a +bitexact` (iPhone เก็บตำแหน่งไว้ทั้งใน tag `location` และใน data track)
- ไฟล์ดิบอยู่ที่ `uploads/<journeyID>/<momentID>` ไม่เคยถูก serve; ไฟล์จริงอยู่ที่ `moments/<journeyID>/<momentID>/full.jpg|video.mp4` และ `thumb.jpg`
- Signed PUT URL อายุ **15 นาที** และบังคับขนาดด้วย header `x-goog-content-length-range: 0,<max>`; Signed GET URL อายุ **1 ชั่วโมง**
- Caption ≤ **300** ตัวอักษร (rune) trim ช่องว่างหัวท้าย
- ใครแปะได้: owner เสมอ; editor/traveler ที่ joined เมื่อ `journeys.members_can_post = true` (ค่าเริ่มต้น `true`, เปลี่ยนได้เฉพาะ owner ผ่าน `PATCH /journeys/:slug`); ทริป legacy (ไม่มี owner) แปะไม่ได้
- ใครลบได้: คนอัปโหลดเอง (ลบได้ทุกเมื่อ **ถึงจะออกจากทริปแล้ว** ตาม BRD 6.2 ข้อ 6) และ owner ของทริป; แก้ caption ได้เฉพาะคนอัปโหลดที่ยังเป็น member
- ใครเห็น: เห็น Moment ได้ก็ต่อเมื่อเห็นทริปแบบ **ไม่ redacted** (stranger ระหว่างทริปยังไม่จบเห็น `[]`); Moment ที่ผูก plan `hidden_from_public` เห็นเฉพาะ member; คนนอกที่เห็นทริปไม่ได้ได้ 404 เหมือน `GET /journeys/:slug`
- ขีดจำกัดกันใช้เกิน: ทริปละไม่เกิน **500** Moment (นับทั้ง pending และ ready), ผู้ใช้หนึ่งคนเริ่มอัปโหลดได้ไม่เกิน **100 ครั้ง/ชั่วโมง** และมี pending ค้างได้ไม่เกิน **40**
- Pending ที่ค้างเกิน **1 ชั่วโมง** ถูกลบ (row + ไฟล์ดิบ) โดย loop ใน `main.go` ทุก 30 นาที
- Process พร้อมกันได้: รูปไม่เกิน 2, วิดีโอไม่เกิน 1 (semaphore ระดับ process) กัน RAM ของ Railway เต็ม
- `STORAGE_DRIVER=local` ใช้ได้เฉพาะ `APP_ENV` development/test (เหมือน log mailer); นอกนั้นต้องเป็น `firebase` ไม่งั้น server ไม่ยอมเปิด
- ลบวันที่มี Moment → **409** `day has moments`; full PUT (`/update`) ของทริปที่มี Moment → **409** `trip has moments` (PUT ลบแล้วสร้าง day ใหม่ทั้งหมด id เปลี่ยน Moment จะหลุด); ลบ plan → Moment ของ plan นั้นย้ายไปอยู่ระดับ day (`plan_id = ""`); ลบทริป → ลบ Moment ทุกอันพร้อมไฟล์ (ไฟล์ลบแบบ best effort, log ถ้าพลาด)
