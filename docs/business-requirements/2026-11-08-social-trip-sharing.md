# Business Requirements: Social Trip Sharing

> ชื่อโปรดักต์ชั่วคราว: **Journey**
> วันที่: 2026-11-08 · สถานะ: Draft v1 (รอ review)

---

## 1. ที่มา

เจ้าของไอเดียไปเที่ยวกับแฟน แล้วแชร์แพลนกันไปมา พอมีเพื่อนขอดูว่าจะไปไหน ก็ส่งลิงก์ให้ดู
เพื่อน ๆ ชอบมาก เพราะเห็นว่าไปที่ไหนก็มีแพลนชัดเจน

จากตรงนี้เลยเกิดไอเดียว่า ถ้ามี platform ที่ทุกคนสร้าง profile แล้วแชร์ทริปของตัวเองได้ ก็น่าจะดี
ให้คนอื่นเห็นว่า ใครไปเที่ยวที่ไหน กับใคร ช่วงไหน และระหว่างทางทำอะไรบ้าง

**สิ่งที่ต่างจาก Facebook / IG / X**

| | Facebook / IG / X | Journey |
|---|---|---|
| เนื้อหาหลัก | โพสต์รูป หลังเที่ยวเสร็จ | **แพลนเที่ยว** ตั้งแต่ก่อนไป ระหว่างไป จนหลังกลับ |
| หน่วยของเนื้อหา | โพสต์เดี่ยว ๆ | **ทริป** ที่มีวัน มีกิจกรรม มีคนร่วมทริป |
| รูป / วิดีโอ | ลอย ๆ ใน feed | ผูกกับวันและกิจกรรมในทริป เลยรู้ว่าถ่ายที่ไหน ตอนไหน |
| คนดูได้อะไร | ความสวยงาม | ความสวยงาม + **แพลนที่เอาไปใช้ต่อได้** |

**แอปที่ใกล้เคียง**
- Polarsteps: เน้นบันทึกเส้นทางระหว่างเที่ยว ไม่เน้นแผน และไม่เน้นโซเชียล
- Wanderlog / TripIt: เน้นวางแผน แต่แชร์แบบโซเชียลไม่ได้

## 2. Vision

> "เห็นว่าเพื่อนจะไปเที่ยวไหน กับใคร ช่วงไหน แล้วหยิบแพลนดี ๆ ไปใช้ต่อได้"

## 3. กลุ่มผู้ใช้

| Persona | ลักษณะ | อยากได้อะไร |
|---|---|---|
| **นักวางแผน** (ต้นแบบ: เจ้าของไอเดีย) | ชอบวางแพลนละเอียด เที่ยวกับแฟน/เพื่อน | ที่วางแพลนร่วมกันกับคนในทริป และอยากอวดแพลน |
| **เพื่อนร่วมทริป** | ไม่ได้วางแพลนเอง แต่ไปด้วย | เปิดดูแพลนง่าย ๆ แปะรูปของตัวเองได้ |
| **คนดู / หาแรงบันดาลใจ** | follow เพื่อน หรือหาที่เที่ยว | เห็นว่าเพื่อนไปไหน และหาแพลนดี ๆ ไปใช้ |

## 4. เป้าหมาย

### Goals
1. สร้าง profile แล้วโชว์ทริปของตัวเอง ทั้งที่กำลังจะไป กำลังไป และไปมาแล้ว
2. ทริปมีหลายคนร่วมได้ เห็นว่าใครไปทริปนี้บ้าง
3. แปะรูปและวิดีโอลงในทริป ผูกกับวัน/กิจกรรม
4. คนอื่นเห็นว่าตอนนี้ใครกำลังเที่ยวอยู่ และช่วงไหนใครมีแพลนไปไหน
5. แชร์ลิงก์ทริปให้คนที่ไม่มีแอปเปิดดูได้ (เหมือนที่ทำตอนแรก)

### Non-goals (ยังไม่ทำในรอบนี้)
- จองโรงแรม / ตั๋วเครื่องบิน / ทัวร์
- หารค่าใช้จ่ายในทริป
- แชทในแอป (ใช้ comment ไปก่อน)
- แผนที่ live tracking แบบ GPS real-time

### Anti-goals (ถ้าเป็นแบบนี้ถือว่าพัง ถึงระบบจะทำงานได้ก็ตาม)
- **คนแปลกหน้ารู้ว่าเราไม่อยู่บ้านช่วงไหน และพักที่ไหน** โดยที่เราไม่ได้ตั้งใจ
- **ถูกเพิ่มเข้าทริปโดยไม่ยินยอม** แล้วโผล่บน profile คนอื่น
- กลายเป็นแค่ IG อีกตัว ที่ feed มีแต่รูป แล้วแพลนหายไป
- วางแพลนยุ่งยากกว่าพิมพ์ใน Notes จนคนเลิกใช้

## 5. คำศัพท์หลัก

| คำ | ความหมาย | มีในระบบแล้วหรือยัง |
|---|---|---|
| **User / Profile** | บัญชีผู้ใช้ มีชื่อ, username, รูป, bio | ❌ ยังไม่มี |
| **Trip** | ทริปหนึ่งทริป (ตอนนี้ในโค้ดเรียก `Journey`) | ✅ มี |
| **Day** | หนึ่งวันในทริป (`ItineraryDay`) | ✅ มี |
| **Plan** | หนึ่งกิจกรรมในวัน (`ActivityPlan`) | ✅ มี |
| **Member** | คนที่ร่วมทริป มี role: owner / editor / traveler | ❌ |
| **Moment** | รูปหรือวิดีโอ ที่แปะในทริป ผูกกับ Day หรือ Plan | ❌ |
| **Follow** | การติดตามคนอื่น เพื่อเห็นทริปใน feed | ❌ |
| **Trip status** | สถานะทริป คำนวณจากวันที่ (ดูข้อ 7.1) | ❌ |
| **Visibility** | ใครเห็นทริปได้บ้าง (ดูข้อ 6) | ❌ |

## 6. Privacy และความปลอดภัย

ส่วนนี้สำคัญที่สุด เพราะไอเดียหลักคือ "ใครดูก็ได้" + "รู้ว่าตอนนี้เที่ยวอยู่ที่ไหน"
สองอย่างนี้รวมกันแล้วบอกคนแปลกหน้าได้ว่าบ้านเราว่างช่วงไหน

### 6.1 ระดับการมองเห็นของทริป

เจ้าของทริปตั้งได้ทีละทริป

| ระดับ | ใครเห็น | ใช้ตอนไหน |
|---|---|---|
| **Public** | ทุกคน รวมถึงคนที่ไม่ได้ login | อยากอวด อยากให้คนเอาแพลนไปใช้ |
| **Followers** | คนที่ follow เรา + คนในทริป | **ค่าเริ่มต้น** (ยืนยันแล้ว 2026-11-08) |
| **Link only** | คนที่มีลิงก์เท่านั้น ไม่โผล่ใน feed / ค้นหา | ส่งให้เพื่อนบางคนดู แบบตอนแรก |
| **Private** | เฉพาะคนในทริป | วางแผนกันเองก่อน |

### 6.2 กฎป้องกันความเสี่ยง *(my call ทั้งหมด ปรับได้)*

1. **ข้อมูลละเอียดเห็นได้เฉพาะ "ระดับที่ไว้ใจ"**
   คนที่ไม่ใช่ follower ระหว่างทริป *ยังไม่จบ* จะเห็นแค่ ชื่อทริป + ประเทศ + เมือง
   ไม่เห็นวันที่หรือเดือน ไม่เห็น Plan รายชั่วโมง และไม่เห็นที่พัก
   (แก้ 2026-11-09: เดิมให้เห็นช่วงเดือน แต่ทริปที่เริ่มเดือนก่อนแล้วยังไม่จบ = กำลังเที่ยวแน่นอน เลยตัดออก)
   พอทริปจบแล้ว ถึงจะเห็นแพลนเต็ม (ถ้าทริปเป็น Public)
2. **Plan ที่เป็นที่พัก ติดป้าย "ซ่อนจากคนนอก" อัตโนมัติ**
   (เช่น plan ที่มี emoji 🏨 หรือเลือกประเภท "ที่พัก") เจ้าของปิดเองได้
3. **สถานะ "กำลังเที่ยว" ไม่โชว์ให้คนนอก** (ดูข้อ 7.5)
4. **รูป/วิดีโอ ลบข้อมูลตำแหน่ง GPS (EXIF) ออกก่อนเก็บเสมอ**
5. **ต้องยินยอมก่อนถูกเพิ่มเข้าทริป** ถูกเชิญแล้วต้องกดรับ ถึงจะโผล่บน profile
6. **ออกจากทริปได้ทุกเมื่อ** และขอให้ลบ Moment ของตัวเองออกได้
7. **Block และ Report** ผู้ใช้ / ทริป / Moment ได้

## 7. Features

ลำดับความสำคัญ: **P0** = ต้องมีใน MVP · **P1** = รอบถัดไป · **P2** = ไว้ทีหลัง

### 7.1 Trip status (P0)

ระบบคำนวณสถานะจากวันที่ของทริป ผู้ใช้ไม่ต้องตั้งเอง

| สถานะ | เงื่อนไข | ป้ายที่โชว์ |
|---|---|---|
| Planning | ยังไม่ได้ใส่วันที่ หรือเจ้าของตั้งเป็น draft | 📝 กำลังวางแผน |
| Upcoming | วันนี้ < `departure_date` | ✈️ อีก N วัน |
| Ongoing | `departure_date` ≤ วันนี้ ≤ `return_date` | 🟢 กำลังเที่ยว (วันที่ X จาก Y) |
| Completed | วันนี้ > `return_date` | ✅ เที่ยวแล้ว |

ใช้ timezone ของปลายทางในการนับวัน *(my call)*

### 7.2 Account & Profile (P0)

- สมัครด้วย Google หรือ email (ส่งลิงก์ login ทางอีเมล ไม่ต้องตั้งรหัสผ่าน) *(my call: บนเว็บสองแบบนี้ครอบคลุมคนส่วนใหญ่ Apple login ไว้ตอนทำแอป iOS)*
- Profile มี: ชื่อแสดง, `@username` (ไม่ซ้ำ), รูป, bio, ประเทศที่เคยไป (นับจากทริปที่จบแล้ว)
- หน้า profile โชว์:
  - **ตอนนี้** : ทริปที่กำลังเที่ยว (ตามกฎ privacy)
  - **กำลังจะไป** : ทริป Upcoming เรียงตามวันใกล้สุด
  - **Travel calendar** : ปฏิทิน/ไทม์ไลน์ ว่าช่วงไหนไปไหน กับใคร
  - **เคยไป** : ทริปที่จบแล้ว + สถิติ (จำนวนประเทศ, เมือง, ทริป)

### 7.3 สร้างและแก้ทริป (P0, มีอยู่แล้วบางส่วน)

- สร้างทริป มี Day และ Plan (ตามที่ API มีอยู่ตอนนี้)
- เพิ่ม: เจ้าของทริป (`owner`), visibility, รูปปก
- **แก้ทีละส่วนได้** เพิ่ม/แก้/ลบ Day หรือ Plan ทีละอัน
  เพราะ API ตอนนี้ update แบบแทนที่ทั้งทริป ถ้าหลายคนแก้พร้อมกัน ข้อมูลจะทับกัน
- เรียงลำดับ Plan ในวันใหม่ได้ ย้าย Plan ข้ามวันได้

### 7.4 ร่วมทริป (P0)

| Role | ทำอะไรได้ |
|---|---|
| **Owner** | ทุกอย่าง รวมถึงลบทริป เปลี่ยน visibility เชิญ/เอาคนออก |
| **Editor** | แก้ Day / Plan ได้, แปะ Moment, เชิญคนเพิ่ม (ถ้า owner อนุญาต) |
| **Traveler** | ไปทริปด้วย โชว์บน profile, แปะ Moment และ comment ได้ แต่แก้แพลนไม่ได้ |

- เชิญผ่าน `@username` หรือลิงก์เชิญ
- คนถูกเชิญต้องกดรับก่อน (ข้อ 6.2 ข้อ 5)
- **ขอจอยทริป** (P1): คนที่เห็นทริป Public กด "ขอร่วมทริป" แล้ว owner อนุมัติ
- หน้าทริปโชว์ avatar คนในทริปทั้งหมด
- จำกัดคนในทริปไม่เกิน 20 คน *(my call)*

### 7.5 สถานะ "กำลังเที่ยว" (P0)

- ทริปที่เป็น Ongoing โชว์ว่า "กำลังเที่ยว [เมือง] วันที่ X จาก Y"
- ใครเห็น:
  - คนในทริป: เห็นเต็ม รวม Plan ของวันนี้
  - Follower: เห็นเมือง + วันที่เท่าไหร่ของทริป
  - คนนอก: **ไม่เห็น** ว่ากำลังเที่ยวอยู่
- ไม่ใช้ GPS ใช้ข้อมูลจากแพลนอย่างเดียว *(my call: ปลอดภัยกว่า และทำง่ายกว่า)*
- มีปุ่ม "ซ่อนสถานะตอนนี้" ปิดชั่วคราวได้

### 7.6 Moments: รูปและวิดีโอ (P0)

- แปะรูป/วิดีโอ ลงใน Day หรือ Plan (ไม่มีโพสต์ลอย ๆ)
- ใส่ caption สั้น ๆ ได้
- ทุกคนในทริปแปะได้ (ยกเว้น owner ปิด)
- ข้อจำกัด *(my call)*:
  - รูป: ไม่เกิน 10 MB ต่อรูป, ไม่เกิน 20 รูปต่อครั้ง
  - วิดีโอ: ไม่เกิน 60 วินาที, ไม่เกิน 100 MB
- ระบบย่อรูปและทำ thumbnail ให้อัตโนมัติ
- ลบ GPS / EXIF ออกก่อนเก็บ
- Moment ใช้ visibility เดียวกับทริป

### 7.7 Follow และ Feed (P0 = follow + feed แบบง่าย)

- Follow ต้องรออนุมัติเป็นค่าเริ่มต้น (`follow_approval` เปิดอยู่) *(Claude ตัดสินใจ 2026-11-09 ปรับกลับได้)*
  - คนที่ follow จะเป็น "คำขอ" ก่อน ยังไม่นับเป็น follower และเห็นเท่าที่คนนอกเห็น จนกว่าเจ้าของบัญชีจะกดรับ
  - เจ้าของบัญชีปิดการอนุมัติได้ในตั้งค่า เมื่อปิด คำขอที่ค้างอยู่จะถูกรับทั้งหมด (ยกเว้นคนที่บล็อกกัน) และ follow ครั้งต่อไปมีผลทันที
  - ผู้ขอยกเลิกคำขอได้ เจ้าของปฏิเสธคำขอหรือลบ follower ได้
- **Feed** เรียงตามเวลา ไม่มี algorithm ใน MVP โชว์เหตุการณ์พวกนี้:
  - "A กำลังจะไป Nagoya กับ B, C · 12–16 ธ.ค."
  - "A เริ่มทริปแล้ว 🟢"
  - "A แปะ 8 รูปใน Day 2 · Osaka Castle"
  - "A เที่ยว Nagoya จบแล้ว ✅"
- **แถว "ตอนนี้ใครเที่ยวอยู่"** ด้านบน feed (คล้าย IG Stories) โชว์เพื่อนที่กำลังเที่ยว

### 7.8 Share link (P0, ต่อยอดจากของเดิม)

- ทุกทริปมีลิงก์ (`slug` มีอยู่แล้ว) เปิดดูบนเว็บได้โดยไม่ต้องมีแอป
- ลิงก์มี preview สวย ๆ เวลาแปะใน LINE / Messenger / X (รูปปก, ชื่อทริป, วันที่)
- คนที่เปิดลิงก์เห็นตาม visibility (ข้อ 6)
- ปุ่ม "สมัครเพื่อ follow" ท้ายหน้า เพื่อดึงคนเข้าแอป

### 7.9 Interaction (P1)

- Like ทริป / Moment
- Comment ในทริป หรือใน Moment
- Save ทริปคนอื่นไว้ดูทีหลัง

### 7.10 ใช้แพลนนี้ (P1)

ไอเดียนี้มาจากที่เพื่อนชอบแพลน
- ทริป Public ที่จบแล้ว มีปุ่ม **"ใช้แพลนนี้"**
- ระบบ copy Day และ Plan ไปเป็นทริปใหม่ของเรา (ไม่ copy รูป ไม่ copy คน และไม่ copy ที่พักที่ถูกซ่อน)
- ทริปใหม่มีเครดิต "ได้แรงบันดาลใจจาก @A"

### 7.11 Discover (P2)

- ค้นหาทริป Public ตามประเทศ / เมือง / ช่วงเดือน / จำนวนวัน
- (API ตอนนี้มี list ทริปแยกตามประเทศอยู่แล้ว ต่อยอดได้)

### 7.12 Notifications (P1)

- ถูกเชิญเข้าทริป / มีคนขอจอยทริป
- มีคนแปะ Moment ในทริปที่เราอยู่
- มีคน follow / like / comment
- เพื่อนเริ่มทริป (ปิดได้)

## 8. หน้าจอหลัก

1. **Feed** : แถวคนที่กำลังเที่ยว + เหตุการณ์จากคนที่ follow
2. **Profile** : ตอนนี้ / กำลังจะไป / travel calendar / เคยไป
3. **Trip** : รูปปก, คนในทริป, สถานะ, tab "แพลน" (Day → Plan) กับ tab "Moments" (แกลเลอรีรูป)
4. **สร้าง / แก้ทริป**
5. **แปะ Moment** : เลือกรูป → เลือก Day/Plan → caption
6. **หน้าเว็บสาธารณะ** ของทริป (จาก share link)
7. **Notifications**
8. **Settings** : privacy ค่าเริ่มต้น, block list

## 9. ตัวชี้วัดความสำเร็จ

| ตัวชี้วัด | ทำไมสำคัญ | เป้าแรก *(my call)* |
|---|---|---|
| % ทริปที่มีคนร่วมทริป ≥ 2 คน | วัดว่าเป็นโซเชียลจริง ไม่ใช่สมุดจดคนเดียว | 50% |
| % ทริปที่มี Moment อย่างน้อย 1 อัน | วัดว่าใช้ระหว่างเที่ยวจริง | 40% |

## 10. เทียบกับระบบที่มีอยู่ตอนนี้

`journey-service` ตอนนี้เป็น Go (Fiber + GORM + PostgreSQL) มี Journey → ItineraryDay → ActivityPlan

**ใช้ต่อได้**
- โครงสร้าง Trip → Day → Plan
- `slug` สำหรับ share link
- List ทริปแยกตามประเทศ (ใช้ทำ Discover)
- Soft delete

**ต้องเพิ่ม**
- `users` + ระบบ login (ตอนนี้ไม่มี auth เลย ทุก endpoint เปิดให้ทุกคนเรียก)
- `journeys.owner_id`, `journeys.visibility`, `journeys.cover_url`
- `journey_members` (user, journey, role, status: invited / joined / left)
- `moments` (journey, day, plan, uploader, type, url, caption) + ที่เก็บไฟล์ (S3 หรือคล้าย ๆ กัน)
- `follows`, `blocks`, `reports`
- `feed_events` หรือคำนวณ feed จากตารางเดิม
- ฟิลด์บน Plan: `category` (เช่น ที่พัก), `hidden_from_public`
- timezone ของปลายทางบน Journey

**ต้องแก้ / ระวัง**
- `PUT /journeys/:slug/update` แทนที่ทั้งทริป ต้องมี endpoint แก้ทีละ Day/Plan เมื่อมีหลาย editor
- `DELETE /journeys` (ลบทั้งหมด) ต้องปิดหรือจำกัดเฉพาะ admin ก่อนเปิดให้คนทั่วไปใช้
- ทุก endpoint ต้องเช็คสิทธิ์ตาม role และ visibility
- service นี้อาจแยกเป็นหลาย service ทีหลัง (user, media, feed) แต่ MVP ทำใน service เดียวก่อนได้ *(my call)*

## 11. ขอบเขต MVP

**แพลตฟอร์ม: เว็บก่อน** (ยืนยันแล้ว)
- เหตุผล: ไอเดียเริ่มจากการส่งลิงก์ให้เพื่อน หน้าเว็บที่เปิดจากลิงก์ได้ทันทีคือตัวดึงคนเข้าแอป
- ออกแบบแบบ mobile-first และ responsive เพราะคนส่วนใหญ่จะเปิดลิงก์จากมือถือ (LINE, IG, Messenger) *(my call)*
- อัปโหลดรูป/วิดีโอผ่าน browser บนมือถือได้ (เลือกจากคลังรูปหรือถ่ายใหม่) *(my call)*
- แอปมือถือ (iOS/Android) ทำทีหลัง เมื่อการแปะรูประหว่างเที่ยวเริ่มใช้เยอะ
- ทำเป็น PWA (ติดตั้งลงหน้าจอมือถือได้) ไว้ก่อนได้ ถ้าไม่เพิ่มงานมาก *(my call, P1)*

**ทำ:** 7.1 Trip status · 7.2 Profile · 7.3 สร้าง/แก้ทริป · 7.4 ร่วมทริป (ไม่รวมขอจอย) · 7.5 กำลังเที่ยว · 7.6 Moments · 7.7 Follow + feed แบบง่าย · 7.8 Share link · ข้อ 6 privacy ทั้งหมด

**ยังไม่ทำ:** ขอจอยทริป, like/comment, ใช้แพลนนี้, Discover, notifications แบบเต็ม
